# `spec` workflow

Specs settle **behavior** (what happens), not mechanism (how). The planner figures out mechanism after.

Relevant crtr skills (load with `crtr skill show <name>`):

- `spec-writing` — investigate, converse, save a behavioral spec
- `review-requirements` — validate requirements doc for EARS compliance and consistency

Use when starting a new feature or capturing what something should do before designing the implementation.
